# Седмичен мониторинг на топ 40 криптоактива

Структурирано наблюдение на първите 40 криптовалути по пазарна капитализация,
с проследяване във времето и **проверка на информацията за достоверност** —
дали новината, движила цената, е факт, наратив или манипулация.

## Основният файл

**[`CRYPTO-TOP40-MONITORING.md`](CRYPTO-TOP40-MONITORING.md)** — това е продуктът.
Един файл, който се натрупва: всяко ново седмично издание се добавя най-отгоре в
РАЗДЕЛ 3, а РАЗДЕЛ 4 събира времевите редове през седмиците.

| Раздел | Съдържание |
|---|---|
| 0 | Как се използва, команда за стартиране |
| 1 | Методика — класове активи A–G, показатели, скор за потенциал 0–10 |
| 2 | **Протокол за проверка на информацията** — йерархия на източниците, червени флагове, рейтинги |
| 3 | Седмичните издания (най-новото отгоре) |
| 4 | Времеви редове — цени, класация, **дневник на достоверността**, скорове |
| 5 | Контролен списък за всяко издание |
| 6 | Ограничения |

## Как работи седмицата

```
понеделник 06:07 UTC          GitHub Actions
  ├─ selftest.py              конвейерът работи ли (спира при провал)
  ├─ fetch_market_data.py     снимка на топ 40 → data/snapshots/ + history.csv
  └─ build_edition.py         чернова на изданието → РАЗДЕЛ 3 + ред в РАЗДЕЛ 4

след това                     аналитик / Claude сесия
  └─ prompts/sedmichen-analiz.md
      проверка на новините по РАЗДЕЛ 2, рейтинги, изводи, дневник на достоверността
```

**Границата между двете е съзнателна.** Скрипт смята съотношения. Скрипт не
преценява дали едно „партньорство“ е истинско. Затова автоматиката оставя
изрични маркери `[ЗА ПОПЪЛВАНЕ]` навсякъде, където се изисква преценка, и никога
не издава рейтинг за достоверност сама.

## Ръчен пуск

```bash
python3 crypto/scripts/fetch_market_data.py     # --top 40 --date YYYY-MM-DD
python3 crypto/scripts/build_edition.py         # --dry-run за преглед без запис
python3 crypto/scripts/selftest.py              # регресионен тест
```

Скриптовете използват само стандартната библиотека на Python 3.11+ — без
зависимости за инсталиране.

## Структурни сигнали

Автоматиката не оценява достоверност, но насочва къде да се търси. Всеки актив
получава сигнал за внимание 0–100 от количествени показатели:

| Сигнал | Праг | Насочва към |
|---|---|---|
| Критична неликвидност | обем/кап. < 0,05% | капитализацията не е реализируема стойност |
| Тънък пазар | обем/кап. < 0,5% | цената е управляема с малък капитал |
| Екстремен оборот | обем/кап. > 100% | модел 4 от 2.4 — изкупен обем |
| Разводняване | FDV/MC ≥ 3× | модел 3 — новина преди отключване |
| Скок в обема | 3× над собствената 8-седмична медиана | необяснена активност |
| Движение без обем | \|24ч\| ≥ 8% при оборот под нормата | тънка книга с поръчки |
| Отскок над/под кохортата | ±2σ и ±3σ (робастни, чрез MAD) | движение без документирана причина |
| Отклонение от котвата | \|цена − 1\| > 0,5% | напрежение при емитент на клас D |
| Липсващ клас | актив извън `classification.json` | автоматично в раздел 3.5 |

Праговете живеят на едно място — в началото на `scripts/analysis.py`.

## Поддръжка

**Нов актив в топ 40** се класифицира автоматично като **G** и влиза в раздел 3.5,
докато не бъде добавен в `data/classification.json`. Това е нарочно: непознат
актив за милиарди долари е сигнал за риск, а не пропуск в конфигурацията.

**Сигналите се задействат постепенно.** Тези, които се опират на собствената
история на актива (скок в обема, движение без обем), изискват поне 4 седмици
натрупани данни. До дотогава работят само тези от текущата снимка.

## Ограничения

Пълният списък е в РАЗДЕЛ 6 на master файла. Най-важното: данните са снимка от
момента, оценката за манипулация е вероятностна, а червен флаг не е доказателство.
Файлът не е инвестиционна препоръка.
